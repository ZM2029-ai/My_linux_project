# 阶段六：远程控制与验收复现

本文按当前工作树整理，供重新构建和验收。本文的步骤及验收结果**尚未在本次编写时重新执行**；表格中的待验收不是通过。阶段六的目标、分工和验收依据见 [阶段六实施方案](../../阶段六实施方案.md)，MQTT 命令和回执格式见 [控制协议](../../protocol/control-command.md)，接口字段见 [HTTP API](../../protocol/http-api.md)。

当前 HTTP 控制有 Basic Auth、角色及 Origin 校验，但 MQTT 客户端尚未实现认证和 TLS，也不能仅凭 MQTT 3.1.1 的接收标志可靠地拒绝所有保留发布。设备注册表的闲置回收也不能抵御持续发送的设备 ID。以下匿名 Broker **仅用于回环接口上的隔离测试**，不要把 MQTT 端口转发到公网或不可信网络。公网验收在这些安全问题解决并复核后进行；不得把下面的测试配置当成公网部署配置。

## 1. 数据流和准备

```text
Windows 浏览器 -- SSH 转发 --> 板端 HTTP（鉴权、命令、审计）
                                   | MQTT 命令/回执
Windows 模拟器 -- SSH 转发 --> 板端 Broker --> 板端 MQTT 采集 --> SQLite
```

准备 Windows PowerShell、OpenSSH、Python 和 [模拟器依赖](../../pc/sensor_sim/requirements.txt)；准备阶段五已验证的 Ubuntu Debian 10 armhf 交叉工具链、SQLite、libmosquitto 和 nlohmann/json 开发文件，以及开发板上的对应运行库、Mosquitto 和 `sqlite3` 命令。SSH 别名及工具链路径按本机实际情况替换。板端时钟、Windows 时钟应正确；历史时间使用北京时间。

以下使用独立目录和新数据库，不覆盖已有数据。`stage6-repro` 若已存在，请先检查内容并更换目录名。先参考 [阶段五复现文档](../阶段五/阶段五-HTTP接口与网页管理端复现.md)确认工具链、SSH 和依赖；阶段六 HTTP 必须打开 `EDGELINK_ENABLE_CONTROL`。

## 2. 打包和交叉构建

Windows 项目根目录 PowerShell：

```powershell
cd E:\Linux_project\demo1
$cfg = Join-Path $env:USERPROFILE '.ssh\ssh-devices\config'
$archive = Join-Path $env:TEMP 'edgelink-stage6-repro-source.tar'
tar -cf $archive gateway web
if ($LASTEXITCODE -ne 0) { throw '源码打包失败' }
ssh -F $cfg -T zm-tailscale 'test ! -e ~/edgelink-stage6-repro && mkdir ~/edgelink-stage6-repro'
if ($LASTEXITCODE -ne 0) { throw 'Ubuntu 目录创建失败或已存在' }
scp -F $cfg $archive 'zm-tailscale:edgelink-stage6-repro/source.tar'
if ($LASTEXITCODE -ne 0) { throw '上传失败' }
ssh -F $cfg zm-tailscale
```

Ubuntu 中执行；`BASE` 必须指向阶段五实际使用的依赖目录，失效时先按阶段四、五文档准备，不要默认更换工具链：

```bash
cd ~/edgelink-stage6-repro
set -e
tar -xf source.tar
BASE=/home/zm/edgelink-stage4.PRyv72
export LD_LIBRARY_PATH="$BASE/host-compat"
test -f "$BASE/relocated-arm.cmake" || { echo '缺少工具链文件'; exit 1; }
test -e "$BASE/sqlite-armhf/usr/lib/arm-linux-gnueabihf/libsqlite3.so" || { echo '缺少 SQLite'; exit 1; }

cmake -S gateway -B arm-http \
  -DCMAKE_TOOLCHAIN_FILE="$BASE/relocated-arm.cmake" \
  -DEDGELINK_ENABLE_CONTROL=ON -DEDGELINK_BUILD_STORAGE_CHECKS=ON \
  -DSQLite3_INCLUDE_DIR="$BASE/sqlite-armhf/usr/include" \
  -DSQLite3_LIBRARY="$BASE/sqlite-armhf/usr/lib/arm-linux-gnueabihf/libsqlite3.so" \
  -DCMAKE_SKIP_RPATH=ON
cmake --build arm-http -- -j2

cmake -S gateway -B arm-mqtt \
  -DCMAKE_TOOLCHAIN_FILE="$BASE/relocated-arm.cmake" \
  -DEDGELINK_MQTT_ONLY=ON -DEDGELINK_ENABLE_SQLITE=ON -DEDGELINK_BUILD_MQTT_CHECKS=ON \
  -DSQLite3_INCLUDE_DIR="$BASE/sqlite-armhf/usr/include" \
  -DSQLite3_LIBRARY="$BASE/sqlite-armhf/usr/lib/arm-linux-gnueabihf/libsqlite3.so" \
  -DCMAKE_SKIP_RPATH=ON
cmake --build arm-mqtt -- -j2
file arm-http/src/http/edgelink_http arm-mqtt/src/mqtt/edgelink_mqtt
readelf -d arm-http/src/http/edgelink_http | grep NEEDED
tar -cf arm-bundle.tar web \
  -C arm-http/src/http edgelink_http \
  -C ../storage edgelink_db device_store_check \
  -C ../../../arm-mqtt/src/mqtt edgelink_mqtt mqtt_state_check mqtt_client_check
exit
```

每步应成功；`file` 应显示 ARM EABI5，HTTP 动态依赖应包括 libmosquitto 和 SQLite。不要在 Ubuntu 宿主机直接运行 ARM 检查程序。

## 3. 部署和启动隔离测试

Windows PowerShell 下载并上传：

```powershell
$cfg = Join-Path $env:USERPROFILE '.ssh\ssh-devices\config'
$bundle = Join-Path $env:TEMP 'edgelink-stage6-repro-arm.tar'
scp -F $cfg 'zm-tailscale:edgelink-stage6-repro/arm-bundle.tar' $bundle
if ($LASTEXITCODE -ne 0) { throw '下载失败' }
ssh -F $cfg -T debian-board-tailscale 'test ! -e ~/edgelink-stage6-repro && mkdir ~/edgelink-stage6-repro'
if ($LASTEXITCODE -ne 0) { throw '板端目录创建失败或已存在' }
scp -F $cfg $bundle 'debian-board-tailscale:edgelink-stage6-repro/arm-bundle.tar'
if ($LASTEXITCODE -ne 0) { throw '上传失败' }
ssh -F $cfg debian-board-tailscale
```

在板端执行。先人工确认端口未被占用；若占用，选新端口并同步更改以下服务和转发参数。检查程序不得显示失败，`ldd` 不应有 `not found`。

```bash
cd ~/edgelink-stage6-repro
tar -xf arm-bundle.tar
ldd ./edgelink_http
ldd ./edgelink_mqtt
./device_store_check
./mqtt_state_check
./mqtt_client_check
ss -lnt | grep -E ':(18884|18080) ' || echo '测试端口空闲'
```

创建只供当前用户读取的账号文件。编辑时自行设置至少 12 个字符、无冒号的不同测试密码；不要使用真实账号密码，也不要提交此文件：

```bash
umask 077
mkdir run
chmod 700 run
${EDITOR:-vi} run/users.conf
chmod 600 run/users.conf
```

文件内容格式如下，把占位文字换成测试密码：

```text
operator:control:replace-with-control-password
viewer:read:replace-with-readonly-password
```

在同一个板端终端启动；保持终端打开，以便保留 PID。`--origin` 必须与浏览器实际地址的源完全一致。

```bash
cd ~/edgelink-stage6-repro
RUN="$PWD/run"
printf '%s\n' 'listener 18884 127.0.0.1' 'allow_anonymous true' 'persistence false' > "$RUN/broker.conf"
/usr/sbin/mosquitto -c "$RUN/broker.conf" > "$RUN/broker.log" 2>&1 &
BROKER_PID=$!
sleep 1
./edgelink_mqtt 127.0.0.1 18884 --db "$RUN/stage6.sqlite3" > "$RUN/mqtt.log" 2>&1 &
MQTT_PID=$!
sleep 2
./edgelink_http "$RUN/stage6.sqlite3" "$PWD/web" 18080 \
  --users "$RUN/users.conf" --origin http://127.0.0.1:18081 \
  --broker 127.0.0.1 18884 > "$RUN/http.log" 2>&1 &
HTTP_PID=$!
sleep 2
kill -0 "$BROKER_PID" "$MQTT_PID" "$HTTP_PID" && echo '三个进程仍在运行'
cat "$RUN/http.log"
tail -n 20 "$RUN/mqtt.log"
```

检查 MQTT 订阅就绪以及 HTTP 日志中的 `Response subscription ready`。若进程退出，先查对应日志；不要继续假定服务已启动。

## 5. 验收操作与预期

以下每项应记录时间、实际状态、命令 ID 和日志位置；与预期不符就记失败或待排查，不应仅因请求返回 202 标记通过。

### 5.1 网页控制及采集回归

1. 两台模拟器都连续输出遥测后，进入 `stage6-01` 详情，点击暂停。先看到等待提示，再看到设备已暂停；模拟器应输出对应回执。
2. 在板端运行下方 SQL，记录两个设备的 `n` 和 `last_id`。至少等待 15 秒后再运行一次。`stage6-01` 数值不再增长，`stage6-02` 持续增长，两个设备仍为 online。允许暂停前已在途的样本先落库，再取基线。
3. 点击恢复，确认成功回执，重复查询：`stage6-01` 的计数和 `last_id` 应重新增长。网页历史曲线和设备列表仍可查询。

```bash
sqlite3 "$RUN/stage6.sqlite3" "SELECT d.device_id,d.presence,count(t.id) AS n,max(t.id) AS last_id FROM devices d LEFT JOIN telemetry t ON t.device_id=d.device_id WHERE d.device_id IN ('stage6-01','stage6-02') GROUP BY d.device_id,d.presence ORDER BY d.device_id;"
```

### 5.2 鉴权、参数和重复提交

在板端另开终端，先启动命令监听并保持运行，以确认拒绝请求没有发布命令（测试期间避免其他人操作网页）：

```bash
mosquitto_sub -h 127.0.0.1 -p 18884 -q 1 -v -t 'edgelink/device/+/command'
```

再开一个板端终端，以实际测试密码替换下面占位符。`curl -u` 把密码放在命令参数中，适合隔离测试；不要将真实密码写入共享终端历史。请求直接发到板端回环，但 `Origin` 模拟浏览器经 SSH 转发访问。只读账号应能查询，不能控制。

```bash
BASE=http://127.0.0.1:18080
ORIGIN=http://127.0.0.1:18081
curl -i "$BASE/api/devices"                                  # 401
curl -i -u 'viewer:READ_PASSWORD' "$BASE/api/devices"        # 200
curl -i -u 'viewer:READ_PASSWORD' -H "Origin: $ORIGIN" -H 'Content-Type: application/json' -d '{"enabled":false}' "$BASE/api/devices/stage6-01/commands" # 403
curl -i -u 'operator:CONTROL_PASSWORD' -H 'Origin: http://invalid.example' -H 'Content-Type: application/json' -d '{"enabled":false}' "$BASE/api/devices/stage6-01/commands" # 403
curl -i -u 'operator:CONTROL_PASSWORD' -H "Origin: $ORIGIN" -H 'Content-Type: application/json' -d '{"enabled":"false"}' "$BASE/api/devices/stage6-01/commands" # 400
curl -i -u 'operator:CONTROL_PASSWORD' -H "Origin: $ORIGIN" -H 'Content-Type: application/json' -d '{"enabled":false}' "$BASE/api/devices/no-such-device/commands" # 404
```

先让 `stage6-01` 上报注册，再停止它的模拟器。向已登记但不在线的设备提交两次相同 POST：第一次应为 202，五秒等待期间第二次应为 409；订阅窗口应只看到第一条命令。保存第一次响应中的 `command_id`，五秒后查询，应为 `timed_out`：

```bash
curl -i -u 'operator:CONTROL_PASSWORD' -H "Origin: $ORIGIN" -H 'Content-Type: application/json' -d '{"enabled":false}' "$BASE/api/devices/stage6-01/commands"
# 立即再执行上一条，然后把返回的 ID 填入下方
ID='替换为第一次返回的command_id'
curl -i -u 'operator:CONTROL_PASSWORD' "$BASE/api/devices/stage6-01/commands/$ID"
```

### 5.3 回执、断线和审计

在隔离 Broker 上进行回执注入。停止 `stage6-01` 模拟器并保持 `stage6-02` 正常运行；每项先按 5.2 提交一个命令并立即记录新的 ID。回执时间使用有效的北京时间字符串，下面使用 GNU `date`：

```bash
ID='替换为当前pending命令的command_id'
TS=$(TZ=Asia/Shanghai date '+%F %T')
mosquitto_pub -h 127.0.0.1 -p 18884 -q 1 -t edgelink/device/stage6-02/response -m "{\"command_id\":\"$ID\",\"success\":true,\"message\":\"wrong device\",\"timestamp\":\"$TS\"}"
# 五秒内查询 stage6-01 的该命令：仍为 pending；不再注入则随后 timed_out。
```

分别新建命令并检查：

- 在五秒内向 `edgelink/device/stage6-01/response` 发布同格式回执，将 `success` 改成 `false`：状态应变为 `failed`，并保留设备说明。
- 向已终态的命令发送重复或相反结果的回执；状态不得改变。另建命令等待 `timed_out` 后再发送成功回执，状态仍应为 `timed_out`。
- 测试模拟器去重时，启动 `stage6-01`，订阅它的 response；向其 command 主题以 QoS 1、非保留连续发送同一合法命令 ID 两次，比较两次回执应相同。使用专用测试 ID，测试后恢复遥测。载荷字段参照 [控制协议](../../protocol/control-command.md)。
- 记录一次待执行命令后断开 Broker，观察无设备确认时命令最终超时；Broker 未就绪时新 POST 应为 503。重新启动原测试 Broker，等待两个采集/控制订阅重新就绪，重新连接模拟器并验证新命令。观察 command 订阅与日志，旧命令不得在重连或重启 HTTP 后再次发布。此项需要实际执行并检查，不能仅凭 clean session 推断通过。

回到保存服务 PID 的板端终端，断开测试 Broker 使用 `kill "$BROKER_PID"`；恢复时按第 3 节原命令重新启动并更新 `BROKER_PID=$!`。断开期间的 PID 变量和日志要保留，避免误杀其他进程。

检查审计，替换命令 ID（只用于测试 ID，避免拼入不可信输入）：

```bash
sqlite3 -header -column "$RUN/stage6.sqlite3" "SELECT id,device_id,occurred_at,operation,detail FROM operation_log WHERE operation='control' ORDER BY id DESC LIMIT 20;"
```

按 `detail` 中的 `command_id` 对照 `actor`、`enabled`、`status` 和 `message`：应有 requested 和相应终态。持续查设备及历史时，确认另一台设备仍在落库；审计失败时还要检查 `http.log`。

### 5.4 公网 HTTPS 验收（待安全修复后执行）

先完成 MQTT 身份认证、每设备主题授权、传输保护和保留发布限制并复核；确认隧道只暴露 HTTP 服务，未暴露 Broker。按选定的隧道工具说明把 HTTPS 地址转发到受控的 HTTP 本地入口。取得 HTTPS 地址后，重启 HTTP，将 `--origin` 改为该地址的完整源（例如 `https://example.invalid`，无末尾路径）；不要把示例域名作为真实地址。
